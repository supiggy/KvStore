# MiniVec 设计取舍

这份文档讲**为什么这么设计、放弃了什么、规模化会在哪崩、跟工业界差在哪**——它(而不是功能数量)是这个项目"不像练手"的关键。面试时白板能从这里任取一节讲 5 分钟。

---

## 1. 目标与非目标

**目标:** 用最少的依赖、从零讲清楚一个向量数据库的完整链路(协议 → 存储 → 索引 → 检索 → 持久化),每个决策都能用第一性原理和自己的基准数字解释。

**非目标:** 替代 Faiss / Milvus。本项目不追求极致性能或分布式,它追求的是**对向量检索系统的第一手工程判断**。明确这一点,才不会掉进"无止境加功能"的练手陷阱。

---

## 2. 关键设计决策

### 2.1 余弦度量 = 归一化 + 内积
入库时若度量为余弦,`vstore_add` / `hnsw_insert` 立刻把向量归一化([distance.c](src/engine/distance.c) 的 `vec_normalize`)。之后检索只做内积 `dist_dot`,**省掉每次重算模长**。这是"归一化后余弦等价于内积"的性能意义。

### 2.2 统一"距离越小越近"
HNSW 内部把三种度量收敛成一个方向([index_hnsw.c](src/engine/index_hnsw.c)):L2 用平方距离;余弦/内积取负相似度。好处:图里所有"更近/更远"的比较只有一个方向,堆、裁剪逻辑不必为 L2 单独写一套。

### 2.3 暴力检索作为正确性基线
`index_flat` 永远正确但 O(N·D)。它的唯一价值是当 HNSW 的 **ground truth**:HNSW 是近似算法,"对"和"错"看起来都"差不多对",没有基线无法判断 recall。这也是 ROADMAP 把 G0/G6 基准排在最前的原因。

### 2.4 存储与索引分家
`vector_store` 只负责"存"(`id → 向量`),"按相似度查"交给 `index_flat` / `index_hnsw`。两个索引对外接口一致,可整体替换。代价见下方局限 §3.1。

## 3. 已知局限(诚实清单)

> 每条都对应 ROADMAP 的一个 goal。**会讲局限,比假装没有局限更显工程成熟度。**

| # | 局限 | 出处 | 影响 | 对应 goal |
|---|------|------|------|-----------|
| 1 | 存储层是定长数组 + 线性扫描;`vstore_add` 每次去重 `find_slot` 是 O(N),建库 O(N²) | [vector_store.c](src/engine/vector_store.c) | 大库插入慢 | (G3 顺带 / 后续 hash 映射) |
| 2 | `capacity` 在 create 时一次性 `calloc`(默认 100 万),内存预占且不能动态扩容 | vector_store.c / minivec.h | 内存浪费 / 容量硬上限 | 后续 |
| 3 | **VDEL 只给 store 打墓碑,不从 HNSW 图里删** → VSEARCH 仍可能返回已删向量 | [parser.c](src/protocol/parser.c) `VDEL` 只调 `vstore_del`;index_hnsw.c 无 delete | **正确性 bug** | **G1** |
| 4 | 持久化只有手动全量快照(SAVE/LOAD,已做原子 rename);**没有 WAL** | [persist.c](src/engine/persist.c) | VADD 后未 SAVE 即崩溃 → 丢全部增量 | **G2** |
| 5 | 单线程 + 引擎零锁;HNSW insert/search 在 IO 线程同步执行 | [server.c](src/net/server.c) | 长操作阻塞事件循环 → p99 抖动 | **G3 / G4**(天然 war story) |
| 6 | 协议把 384 个 float 当文本传,单条 VADD ~3.5KB,解析要 `strtof` ×384 | parser.c | 带宽与 CPU 浪费 | G5 |
| 7 | 距离是标量循环,无 SIMD;向量是 float32,无量化 → 内存 = N×384×4B | distance.c / minivec.h | CPU 与内存 | G7 / G8 |
| 8 | LOAD 是追加语义(不清空),`vstore_count` 含墓碑 | persist.c / vector_store.c | 重复 LOAD 会叠加 | 后续 |

## 4. 规模化:10 亿向量会怎么崩,怎么改

> 这一节是**面试加分点**,先给骨架,深化由你来写(填进你自己的分析与取舍)。

- **内存墙:** 10 亿 × 384 × 4B ≈ **1.4 TB**,单机放不下。→ 量化(G7 int8 → 1/4,G8 PQ → 更狠)+ 分片。`← 你补充:量化精度损失如何用 recall 量化?`
- **建图墙:** §3.1 的 O(N²) 去重 + HNSW 图随机访问导致的 cache miss,在十亿级会非常痛。→ `← 你补充:hash 映射 / 分段建图 / mmap?`
- **持久化墙:** 全量快照在 TB 级不可行。→ 增量 WAL + 后台 compaction。`← 你补充:快照与 WAL 的截断点?`
- **并发墙:** 单线程吞吐封顶。→ 分片 + 每分片一把锁 + 多 reactor。`← 你补充:为什么分片比全局锁好?`
- **分布式(选做):** 路由层 + 副本。`← 你补充:CAP 取舍?`
