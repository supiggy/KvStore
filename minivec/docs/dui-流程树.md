# 流程树 · dui.c(KNN topK 小顶堆)

> 本文是 `dui.c` 的流程树讲解。`dui.c` = 给 `index_flat.c` 用的**固定容量 K 的小顶堆**,
> 元素是 `search_result_t {id, score}`,服务"找 score 最大的 K 个"。
> 配套见 `数据结构知识点.md`(通用堆原理)、`讲解-02-index_flat.md`(怎么用)。

---

## 0. 一句话定位

> 维护一个**只装 K 个**的小顶堆,堆顶 `h[0]` 永远是这 K 个里 **score 最小** 的那个 = **门槛**。
> 扫全库时,谁的 score 打得过门槛,就把门槛踢掉、自己进来。扫完,堆里就是最大的 K 个。

```text
小顶堆(K=3)示意,堆顶是最小:
            h[0]=7   ← 门槛(当前 3 个里最小)
           /      \
        h[1]=8    h[2]=9
```

---

## 1. 数组下标关系(堆的地基)

堆是数组存的完全二叉树,父子靠下标算,不建真树:
```text
当前 i :  父 = (i-1)/2 ,  左孩子 = 2*i+1 ,  右孩子 = 2*i+2
```

---

## 2. 五个函数 + 调用关系

```text
topk_push(h, &size, K, id, score)        ← 对外主入口:扫描时每个候选调一次
  ├─ 堆没满(size < K)  → 末尾放入 → heap_siftup     上浮
  └─ 堆满了 且 score>门槛 → 覆盖堆顶 → heap_siftdown   下沉
heap_siftup / heap_siftdown
  └─ sr_swap                              交换两个 search_result_t
cmp_desc                                  全部收集完后,qsort 降序输出用
```

## 3. 逐函数流程树

### 3.1 `sr_swap` — 交换工具
```text
sr_swap(a, b)
  └─ 临时变量倒一手:t=*a; *a=*b; *b=t
```

### 3.2 `heap_siftup` — 上浮(插入后用)
```text
heap_siftup(h, i)            i = 刚放进末尾的位置
  └─ while i > 0:
        parent = (i-1)/2
        if h[i].score < h[parent].score:   小顶堆:我比父更小 → 该在上面
            sr_swap(h[i], h[parent])
            i = parent                      继续往上比
        else:
            break                           父已经比我小,堆性质满足,停
```
**讲解**:新元素从底部往上"冒泡",一路和父亲比,比父亲小就交换上去,直到父亲更小为止。

### 3.3 `heap_siftdown` — 下沉(替换堆顶后用)
```text
heap_siftdown(h, n, i)       i = 0(从堆顶开始),n = 当前堆大小
  └─ while true:
        l = 2i+1; r = 2i+2; smallest = i
        if l < n && h[l].score < h[smallest].score: smallest = l
        if r < n && h[r].score < h[smallest].score: smallest = r
        if smallest == i: break             我已比两个孩子都小,停
        sr_swap(h[i], h[smallest])          和更小的孩子换
        i = smallest                        继续往下沉
```
**讲解**:被换到堆顶的新元素往下"沉",每层和**更小的那个孩子**交换,直到比两个孩子都小。
注意 `l < n`、`r < n` 是边界保护——孩子下标可能越界(没有孩子)。

### 3.4 `topk_push` — 主逻辑(★ 核心)
```text
topk_push(h, &size, K, id, score)
  ├─ if size < K:                    堆还没满 K 个
  │     h[size] = {id, score}        放到末尾
  │     heap_siftup(h, size)         上浮归位
  │     size++
  │
  └─ else if K>0 && score > h[0].score:   堆满了,且打得过门槛 h[0]
        h[0] = {id, score}           覆盖堆顶(把最差的挤掉)
        heap_siftdown(h, size, 0)    新堆顶下沉归位
        (size 不变,始终 = K)

  打不过门槛的候选 → 直接丢弃(两个分支都不进)
```
**讲解**:这就是 KNN 的"门槛思想"。两种情况:没凑够 K 个先来者不拒(siftUp);凑够了就只收"比当前最差的还好"的(替换堆顶 + siftDown)。

### 3.5 `cmp_desc` — 降序排序器
```text
cmp_desc(a, b)
  └─ 按 score 大的排前面(qsort 用):
       sa<sb → 1   sa>sb → -1   相等 → 0
```
**讲解**:堆数组本身是无序的(只保证堆顶最小)。最后要给用户"从最像到最不像",所以收集完用 `qsort` 按 score 降序排一遍。

## 4. 完整执行 trace(看堆数组怎么变)

喂入 `(id, score)` 序列、`K=3`:`(0,5) (1,1) (2,9) (3,3) (4,7) (5,2) (6,8)`
下面每步显示堆数组 `[(score,id) ...]`,`h[0]` 是门槛:

```text
push(0,5): 未满 → 末尾入,siftup 无父         heap = [(5,0)]
push(1,1): 未满 → 末尾入,1<5 上浮            heap = [(1,1),(5,0)]              门槛=1
push(2,9): 未满 → 末尾入,9<1? 否,不动        heap = [(1,1),(5,0),(9,2)]       门槛=1  (满了)
push(3,3): 满, 3>门槛1 → 覆盖堆顶,下沉无更小  heap = [(3,3),(5,0),(9,2)]       门槛=3
push(4,7): 满, 7>门槛3 → 覆盖堆顶[(7,4)..],
           下沉:孩子5更小→换                heap = [(5,0),(7,4),(9,2)]       门槛=5
push(5,2): 满, 2>门槛5? 否 → 丢弃            heap = [(5,0),(7,4),(9,2)]       门槛=5
push(6,8): 满, 8>门槛5 → 覆盖堆顶[(8,6)..],
           下沉:孩子7更小→换                heap = [(7,4),(8,6),(9,2)]       门槛=7
```

扫描结束,堆里 = `{(7,4),(8,6),(9,2)}` —— 正是 score 最大的 3 个。
`qsort(cmp_desc)` 后输出:`(9,2) (8,6) (7,4)` → **id 2, 6, 4**。

> 这跟我们之前在 Docker 里跑的测试结果**完全一致**(top3: id2=9, id6=8, id4=7),说明这套堆是对的。

## 5. 为什么是"小顶堆"(KNN 关键,必懂)

要找 **最大** 的 K 个,却用 **小顶堆**——反直觉,但堆顶必须是"最小"才能当门槛:

```text
小顶堆堆顶 = 当前 K 个里最差(最小)的 = 入选门槛
  新候选 > 门槛 → 它比"现有最差的"还好 → 踢掉最差的,自己进来
  新候选 ≤ 门槛 → 它连最差的都不如 → 直接丢
```
如果用大顶堆,堆顶是最大值,你没法 O(1) 知道"当前最差的是谁",就没法快速判断"该不该踢"。

复杂度:每个候选 O(log K),N 个候选共 **O(N log K)**,额外空间 **O(K)**。优于全排序 O(N log N)。

## 6. 一句话背诵 & 面试

> **背诵**:topK 最大用**小顶堆**,堆顶是门槛(K 个里最小)。push 两分支:没满就 siftUp 入堆,满了且 score>门槛就覆盖堆顶再 siftDown。下标:父 `(i-1)/2`、左 `2i+1`、右 `2i+2`。最后 qsort 降序输出。

**Q:这个 `topk_push` 满了之后为什么是"覆盖堆顶 + 下沉"而不是先 pop 再 push?**
> 因为堆大小要恒定为 K。直接把新元素写到堆顶 `h[0]`(覆盖掉最差的门槛),再 siftDown 让它沉到正确位置,一步 O(log K) 就完成"踢掉最差 + 放入新值",比 pop 再 push 两次操作更省。

**Q:siftDown 里 `l<n && r<n` 的判断能省吗?**
> 不能。它是边界保护:某些节点没有左/右孩子,下标 `2i+1`、`2i+2` 会越过堆的有效范围 `n`,不判断就会读到堆外的脏数据,导致比较和交换出错。
