# 讲解 02 · index_flat(暴力检索)

> 模块定位:遍历全库算 topK。O(N×D),慢,但**永远正确**。
> 它的真正使命不是上线,而是当 HNSW 的**标准答案(ground truth)**。
> 难度 ★★☆。对应面试知识分支 3:KNN vs ANN。

---

## 0. 为什么要先写这个"慢"的

HNSW 是**近似**算法——它找的"最近邻"可能不是真的最近。
你写完 HNSW,怎么知道它对不对?只能拿一个"一定正确"的结果对照。
那个一定正确的结果,就是暴力检索算出来的。

```text
recall@10 = (HNSW 返回的 10 个 ∩ 暴力返回的 10 个) / 10
```
没有 index_flat,你的 HNSW 写错了都发现不了。**所以它必须第一个正确。**

---

## 1. 要实现的函数

```c
int flat_search(const vector_store_t *s, const vec_t *query, int topk,
                metric_t metric, search_result_t *out);
```
遍历全库,把最相似的 `topk` 个按相似度从高到低写进 `out[]`,返回实际个数。

---

## 2. 流程树

```text
flat_search(s, query, topk, metric, out)
  ├─ 建一个大小为 topk 的"最优集合"(用堆)
  │
  ├─ for i in [0, vstore_count(s)):
  │     item = vstore_at(s, i)
  │     if item->vec == NULL: continue          ← 跳过墓碑(已删除)
  │     score = 按 metric 调 dist_dot / dist_l2sq / dist_cosine(query, item->vec)
  │     ├─ 堆未满 topk 个 → 直接放入
  │     └─ 堆已满 → 若 score 比堆顶"更优",弹堆顶、放入新的
  │
  ├─ 把堆里 topk 个取出,按相似度从优到劣排序,写进 out[]
  └─ return 实际个数(可能 < topk,当库里不足)
```

---

## 3. 核心难点:topK 为什么用堆,怎么用

### 3.1 为什么不直接全排序
全部算完再排序:O(N log N)。
但你只要前 K 个,用堆边扫边维护:O(N log K)。当 N=100万、K=10,差距巨大。

### 3.2 堆的方向(最容易绕晕的点)
关键认知:**要找"最大的 K 个",用小顶堆;要找"最小的 K 个",用大顶堆。** 反直觉,但对。

```text
找最大 K 个(COSINE/DOT,越大越相似):
  用【小顶堆】,堆顶 = 当前这 K 个里"最差(最小)的那个"
  新元素只要 > 堆顶,就有资格挤掉堆顶进来

找最小 K 个(L2,越小越相似):
  用【大顶堆】,堆顶 = 当前这 K 个里"最差(最大)的那个"
  新元素只要 < 堆顶,就挤掉堆顶
```
直觉:堆顶守的是"门槛"——这 K 个里最弱的。新人打得过门槛才放进来,然后门槛上移。

### 3.3 度量方向统一(一个好用的简化技巧)
COSINE/DOT 是"越大越近",L2 是"越小越近",方向相反,堆的逻辑要分两套很烦。
技巧:**内部统一成"分数越大越优"**:
```text
COSINE / DOT : 分数 = dist 值          (本来就越大越优)
L2           : 分数 = -dist_l2sq       (取负,于是也变成越大越优)
```
这样堆永远是"小顶堆找最大",一套逻辑通吃。输出时记得 L2 的 score 再取回正。

---

## 4. 子任务拆解(建议顺序)

1. **先不用堆,用全排序版跑通**(简单、好对照):把所有 `(id, score)` 存数组,`qsort` 后取前 K。先证明检索逻辑对。
2. 跑通后,再换成**堆**(性能版),用全排序版结果对照堆版,确保一致。
3. 处理边界:库里不足 topk;全是墓碑;topk<=0。

> 学习阶段,第 1 步的全排序版完全够用,堆是优化。别因为堆卡住而停在第一步。

---

## 5. 坑清单

| 坑 | 说明 |
|----|------|
| 忘了跳过墓碑 | `vstore_del` 是墓碑删除,`item->vec==NULL`,不跳过会对空指针算距离 → 崩 |
| 堆方向搞反 | 找最大用小顶堆,搞反会留下最差的 K 个 |
| L2 当成越大越优 | L2 越小越近,方向相反;用"取负统一"最省心 |
| 输出没排序 | 堆里是无序的,取出后要再排一次序 |
| 库不足 topk | 返回值要是实际个数,不能假装有 topk 个 |

---

## 6. 验证方法

```text
插入(VADD)几个好认的向量,比如:
  id=1: [1,0,0,...]
  id=2: [0.9,0.1,0,...]
  id=3: [0,1,0,...]
VSEARCH 3 [1,0,0,...]
  期望:1 最相似,2 次之,3 最远 → 肉眼核对顺序
```
全排序版和堆版结果必须完全一致。

## 7. 一句话背诵 & 面试回答

> **背诵**:暴力检索 O(N×D),遍历全库算距离,用大小为 K 的堆留住最优 K 个;找最大用小顶堆,堆顶是门槛。它慢但永远对,是 HNSW 的标准答案。

**Q:从一百万个向量里找最相似的 10 个,你怎么做?**
> 最朴素是暴力:遍历全部算距离,O(N×D)。只要 top10 的话不必全排序,用一个大小为 10 的小顶堆边扫边维护,复杂度降到 O(N log 10)。堆顶始终是当前 10 个里最差的,新向量打得过堆顶才替换进来。数据量再大就得上 ANN 索引比如 HNSW,用近似换速度。

**Q:为什么找最大的 K 个反而用小顶堆?**
> 因为堆顶要守住"这 K 个里最弱的那个"当门槛。小顶堆堆顶是最小值,新元素只要比这个最小值大就有资格进来、顶掉它,门槛随之抬高。最后留下的就是最大的 K 个。
