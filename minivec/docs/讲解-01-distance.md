# 讲解 01 · distance(距离 / 相似度)

> 模块定位:全库最底层、最热的代码。无状态纯函数,输入两个向量输出一个数。
> 难度 ★☆☆,适合热身。先写对,再写快(SIMD 是后期优化,别一上来就做)。
> 对应面试知识分支 2:相似度度量。

---

## 0. 先建立直觉:三种度量在比什么

向量是"语义坐标"。判断两个向量像不像,有三种角度:

```text
内积 dot     : 投影大小。两向量同向且都长 → 大
L2 距离      : 两点直线距离。越近越像 → 小
余弦 cosine  : 两向量夹角。只看方向,不看长度 → 越接近1越像
```

一句话:**L2 看"距离",余弦看"夹角",内积是两者的桥梁。**

---

## 1. `dist_dot` —— 内积

### 流程树
```text
dist_dot(a, b, dim)
  ├─ s = 0
  ├─ for i in [0, dim):
  │     s += a[i] * b[i]
  └─ return s
```

### 讲解
就是对应位置相乘再累加。它是另外两个度量的"原料":
- 余弦的分子就是 dot
- 归一化之后,余弦 == dot

### 实现要点
- 一个 for 循环搞定,别想复杂
- 返回 `float`,累加用 `float` 即可(维度不大时精度够;追求精度可用 `double` 累加)

### 优化预留(现在别做)
循环可用 AVX 一次算 8 个 float —— 这是 SIMD,留到 M6 工程化阶段。

---

## 2. `dist_l2sq` —— L2 距离的平方

### 流程树
```text
dist_l2sq(a, b, dim)
  ├─ s = 0
  ├─ for i in [0, dim):
  │     d = a[i] - b[i]
  │     s += d * d
  └─ return s          ← 注意:不开方
```

### 讲解:为什么不开方(高频面试点)
我们只用距离来**排序**(找最近的 K 个)。开方是单调函数:
```text
若 d1² < d2²  则  d1 < d2
```
所以排序结果完全一样,但每次省一个 `sqrtf`。在 O(N×D) 的热路径上,省下的就是真金白银。
> 命名特意叫 `l2sq`(squared)提醒自己:这是平方,不是真距离。

---

## 3. `dist_cosine` —— 余弦相似度

### 流程树
```text
dist_cosine(a, b, dim)
  ├─ dot = sum(a[i]*b[i])
  ├─ na  = sqrt(sum(a[i]^2))      a 的模长
  ├─ nb  = sqrt(sum(b[i]^2))      b 的模长
  ├─ if na==0 or nb==0: return 0   除零保护
  └─ return dot / (na * nb)
```

### 讲解
余弦 = `dot / (|a|·|b|)`,几何意义是两向量夹角的 cos 值,范围 [-1, 1]:
```text
 1   完全同向(最相似)
 0   垂直(无关)
-1   完全反向
```
它**只看方向、不看长度**——这正是文本语义检索想要的(一句话说三遍,向量更长,但意思没变)。

### 实现要点
- 可以一趟循环同时累加 `dot / sum(a²) / sum(b²)`,省两遍遍历
- 必须做除零保护(零向量模长为 0)
- 需要 `sqrtf` → 记得 `#include <math.h>`,链接 `-lm`(Makefile 已带)

## 4. `vec_normalize` —— 原地归一化(★ 性能枢纽)

### 流程树
```text
vec_normalize(v, dim)
  ├─ norm = sqrt(sum(v[i]^2))
  ├─ if norm == 0: return         零向量不动,避免除零
  └─ for i in [0, dim): v[i] /= norm
```

### 讲解:归一化后,余弦退化成内积(必考)
归一化 = 把向量"压"成长度 1(单位向量)。如果 a、b 都已归一化,则 `|a|=|b|=1`:
```text
cosine(a,b) = dot(a,b) / (1 * 1) = dot(a,b)
```
所以工程上的标准做法是:
```text
入库时:  vstore_add 里 normalize 一次       (已在 vector_store.c 调用,等你实现)
查询时:  parser 里对 query normalize 一次    (已在 parser.c 调用,等你实现)
检索时:  直接用 dist_dot,不再算模长          → 省掉每次检索的 sqrt
```
**这就是 `vec_normalize` 是空操作时 VSEARCH 也"能跑但不准"的原因**——存的、查的都没归一化,内积≠余弦。你把它实现了,余弦检索才真正生效。

## 5. 坑清单

| 坑 | 说明 |
|----|------|
| 余弦忘了除零保护 | 零向量模长 0,会 NaN/inf |
| L2 画蛇添足开方 | 排序不需要,白白变慢 |
| 忘了 `-lm` | 用 `sqrtf` 不链接数学库会报 undefined reference(Makefile 已加) |
| 归一化漏了一处 | 入库归一化了、查询没归一化(或反之),余弦结果就错 |
| float 精度 | 维度很大时累加误差;学习阶段可忽略,追求精度用 double 累加 |

## 6. 验证方法

写个临时 `main`,手算两个简单向量再核对:
```text
a = [1, 0, 0, ...]   b = [1, 0, 0, ...]
  dot = 1     l2sq = 0     cosine = 1

a = [1, 0]   b = [0, 1]
  dot = 0     l2sq = 2     cosine = 0

a = [3, 4]   (模长 5)
  normalize 后 = [0.6, 0.8]
```

## 7. 一句话背诵 & 面试回答

> **背诵**:内积是原料,L2 看距离(不开方省 sqrt),余弦看夹角;归一化后余弦就等于内积,所以入库和查询各归一化一次,检索时只算内积。

**Q:余弦相似度和内积什么关系?**
> 余弦 = 内积 / 两向量模长之积。如果向量都归一化成单位长度,模长都是 1,余弦就等于内积。所以工程上入库和查询时各做一次归一化,检索热路径就只算内积,省掉每次的模长计算。

**Q:为什么 L2 距离实现里不开方?**
> 因为检索只用距离排序,而开方是单调的,平方距离的大小关系和真实距离一致,排序结果相同。省掉 sqrt 能在 O(N×D) 的热路径上提速。
