## 0. 三引擎的共同设计（先讲抽象，显工程素养）

array / hash / rbtree 三个引擎对外是**统一的语义契约**：

| 操作 | 返回值约定 |
|------|-----------|
| `set` | `0` 成功 / `1` key 已存在(不覆盖) / `-1` 出错 —— SET 只负责"新增"，改值走 MOD |
| `get` | value 指针 / `NULL` 不存在 |
| `del` / `mod` | `0` 成功 / `1` 不存在 / `-1` 出错 |

### 两个关键共性实现

**① `kvstore_strdup` —— 所有权（ownership）拷贝**
- 传入的 key/value 是网络层 buffer 的指针，**生命周期不归引擎管**；直接存指针，buffer 复用后数据就脏了。
- 必须 `malloc + strcpy` 拷一份，自己持有、自己释放。
- 追问「为什么不用标准库 `strdup`」→ `strdup` 是 POSIX 不是 C 标准；且这里要走自定义 `kvstore_malloc`，方便以后换 slab 分配器。

**② 分步 malloc 的「失败回滚」**
- 先分配 node，再 key，再 value，**任何一步失败都要释放前面已分配的再返回 `-1`**，否则内存泄漏。
- 这是 C 手动内存管理的标准防泄漏写法（C++ 用 RAII，Go/Java 靠 GC）。

## 1. 哈希表（链地址法 / 拉链法）

### 1.1 数据结构

```
桶数组 nodes[] 存指针，冲突的 key 挂成单链表：

nodes[0] -> NULL
nodes[1] -> {k1,v1} -> {k7,v7} -> NULL   // 1 和 7 冲突，串成链
nodes[2] -> {k2,v2} -> NULL
```

```c
struct hashnode { char *key; char *value; struct hashnode *next; };
struct hashtable { struct hashnode **nodes; int max_slots; int count; };
```

### 1.2 哈希函数：BKDR

```c
hash = hash * 131 + (unsigned char)*key++;   // 逐字符累乘累加
```

| 追问 | 回答 |
|------|------|
| 为什么 `(unsigned char)` 强转？ | `char` 多数平台有符号，高位字节(>127)会符号扩展成负数污染哈希值；转无符号避免 |
| 为什么返回 `unsigned int`？ | 让溢出按 2³² 自然回绕（无符号溢出有定义；有符号溢出是 UB）|
| 131 是什么？ | 经验上冲突少的乘子，31/131/1313 都常见（Java `String.hashCode` 用 31）|

### 1.3 核心操作要点

- **find 复用 + 回传 slot**：`find(key, &slot)` 查找时顺便把桶下标带回，`set` 查重后插入**不用再算一次哈希**。
- **头插法**：`node->next = 桶头; 桶头 = node;` → O(1)，不用遍历到链尾。
  - 追问「头插 vs 尾插」→ 头插快但不保插入顺序；Java 8 前 HashMap 头插，多线程扩容会成环，8 后改尾插。
- **删除记前驱**：单链表删除经典套路，用 `prev` 记前驱，分「删头节点（桶直接指向 next）」和「删中间（prev 跨过当前）」。**链表基本功，要能白板写。**

### 1.4 复杂度

| 情况 | 增删查 |
|------|--------|
| 哈希均匀 | 平均 **O(1)** |
| 极端冲突（全挤一个桶） | 退化 **O(n)** |

装载因子 = `count / max_slots`，过大查询变慢。

### 1.5 本实现的弱点（主动承认 = 加分）

1. **不扩容（no rehash）**——桶数 create 时固定。装载因子过大链变长退化 O(n)。
   - **改进**：装载因子超阈值时，新建 2 倍桶数组，遍历旧表把每个节点重新哈希搬过去。
2. **全局静态单例**——只能一张表、非线程安全。
3. **最坏 O(n)**——Java 8 对策：链长 >8 转红黑树。

## 2. 红黑树（自平衡 BST，标准 CLRS 实现）

### 2.1 五条性质

1. 节点非红即黑
2. 根是黑
3. 叶子(NIL)是黑
4. 红节点的孩子都是黑（**不能有连续红**）
5. 任一节点到所有叶子路径的**黑节点数相同**（黑高一致）

> **凭什么 O(log n)**：由性质 4、5 推出「最长路径 ≤ 2×最短路径」，所以树高 O(log n)，近似平衡。

### 2.2 哨兵 nil（精髓）

用**一个**黑色哨兵节点代替所有 NULL 叶子，两大用处：

1. 旋转/修复时不用到处判 `if (x == NULL)`，代码大幅简化。
2. 哨兵的 `parent` 可被临时写入 → 删除修复时能从 nil 往上回溯（删除时 `x->parent = y` 哪怕 x 是 nil 也成立）。

### 2.3 旋转（重新平衡的原子操作）

```
   x              y
    \    左旋     / \
     y   ==>     x   c
    / \           \
   b   c           b
```

- **核心认知**：旋转保持 BST 有序性不变，只改高度/结构。右旋是左旋的镜像。
- 三步走：①改 x、y 的孩子指向 ②y 接到 x 原父亲位置 ③x 挂到 y 下。**每步都要同步维护 `parent`，最易写错。**

### 2.4 插入修复 —— 3 个 case

**新节点一律先染红**。为什么？→ 插红不破坏黑高（性质 5），只可能破坏性质 4（连续红）；插黑必破坏黑高，更难修。

父节点也是红 → 连续红，看**叔叔**：

| case | 条件 | 操作 |
|------|------|------|
| 1 | 叔叔红 | 父、叔变黑，祖父变红，问题上移到祖父（`z=祖父` 续循环）|
| 2 | 叔叔黑，z 在内侧 | 对父旋转，转成 case 3 |
| 3 | 叔叔黑，z 在外侧 | 父变黑、祖父变红，旋转祖父，结束 |

「父亲是右孩子」是左右镜像。最后强制根染黑。**插入最多 2 次旋转。**

### 2.5 删除 —— 最难，分两层

**第一层：BST 删除（三种情况）**
- z 没左孩子 → 用右孩子顶替
- z 没右孩子 → 用左孩子顶替
- z 有两孩子 → 找右子树最小值 y（**中序后继**）顶替 z

**关键变量 `y_original_color`**：记录「真正从树里消失的那个颜色」。只有删**黑**节点才破坏黑高，才需要 `delete_fixup`；删红节点直接收工。

**`transplant`（子树移植）**：只改「u 父亲的指向」和「v 的 parent」。对 v 是 nil 也写 `v->parent`——哨兵的用处。

**第二层：删除修复 —— 4 个 case**（围绕**兄弟 w**，x 背负「额外一重黑」）：

| case | 条件 | 操作 |
|------|------|------|
| 1 | 兄弟红 | 旋转+变色，转成 2/3/4 |
| 2 | 兄弟黑 + 两孩子都黑 | 兄弟变红，额外黑上移到父亲 |
| 3 | 兄弟黑 + 近侄红远侄黑 | 旋转兄弟，转成 case 4 |
| 4 | 兄弟黑 + 远侄红 | 变色+旋转父亲，补上黑高，结束 |

**删除最多 3 次旋转。**

### 2.6 复杂度

增删查均稳定 **O(log n)**，且天然有序（中序遍历即升序），支持范围查询 / min / max / 前驱后继。

### 2.7 插入修复图解（白板逐步推演）

> 约定：节点后缀 `:R`=红，`:B`=黑。以下均为「父亲 p 是祖父 g 的**左**孩子」的情形，
> 父亲是右孩子时整体左右镜像（旋转方向对调）。`u`=叔叔，`z`=当前节点。
> 进入循环的前提：`z` 红且 `z` 的父亲 `p` 也红（连续红，违反性质 4）。

**Case 1：叔叔 u 红** —— 纯变色，把矛盾上移

```
        修复前                              修复后（z 跳到 g 继续循环）
         g:B                                   g:R   ← z（新的待检查点）
        /   \                                 /   \
      p:R    u:R          ──变色──>          p:B    u:B
      /                                      /
    z:R ←                                  z:R
```
操作：`p、u 变黑`，`g 变红`，`z = g`。
为什么：p、u 都变黑后，经过 g 左右子树的黑高各 +1 保持一致；g 变红可能和 g 的父亲再次连续红，所以把 z 抬到 g 继续检查。

**Case 2：叔叔 u 黑，z 是内侧（右孩子）** —— 先左旋转成外侧

```
        修复前                          z=p 后，左旋(p)  →  变成 Case 3 的形状
         g:B                                   g:B
        /   \                                 /   \
      p:R    u:B          ──左旋(p)──>       A:R    u:B      A=原 z（红），升为 g 的左孩子
        \                                    /
        z:R ←（内侧右孩子）                 p:R ←  z 指针现在指这里（外侧左孩子）
```
操作：`z = z.parent`（z 指向老 p），`左旋(z)`。本身不改颜色，只把「拐弯」的形状捋直，交给 Case 3 收尾。

**Case 3：叔叔 u 黑，z 是外侧（左孩子）** —— 变色 + 右旋祖父，结束

```
        修复前                              右旋(g) 后（循环结束，p 已黑）
         g:B                                   p:B
        /   \                                 /   \
      p:R    u:B          ──右旋(g)──>       z:R    g:R
      /                                              \
    z:R ←（外侧左孩子）                              u:B
```
操作：`p 变黑`，`g 变红`，`右旋(g)`。右旋后 p 顶到子树根且为黑，左右黑高补齐，连续红消除，循环终止。

> **一句话记忆**：叔红→变色上移；叔黑内侧→旋成外侧；叔黑外侧→变色+旋转收尾。**插入最多 2 次旋转。**

### 2.8 删除修复图解（白板逐步推演）

> 约定：`x` 是顶替到空位的节点，**背负"额外一重黑"**（双黑），图中标 `x:B*`（`*`=额外黑）。
> `w`=兄弟。以下为「x 是父亲**左**孩子」的情形，右孩子镜像。`p:?` 表示 p 颜色任意。
> 目标：把这重"额外黑"消化掉（要么找到一个红节点吸收，要么上移到根）。

**Case 1：兄弟 w 红** —— 旋转+变色，转成 2/3/4

```
        修复前                              左旋(p) 后，w 重新取右兄弟
         p:B                                   w:B
        /   \                                 /   \
     x:B*    w:R          ──左旋(p)──>       p:R    wr:B
            /   \                           /   \
          wl:B   wr:B                    x:B*   wl:B  ← x 的新兄弟变 wl:B（黑），进入下面三种
```
操作：`w 变黑`，`p 变红`，`左旋(p)`，`w = x.parent.right`。x 仍是双黑，但兄弟已变黑，可套用 2/3/4。

**Case 2：兄弟 w 黑 + w 的两个孩子都黑** —— 额外黑上移到父亲

```
        修复前                              修复后（x 跳到 p）
         p:?                                   p:?  ← x（额外黑交给了 p）
        /   \                                 /   \
     x:B*    w:B          ──w 变红──>        x:B    w:R
            /   \                                  /   \
          wl:B   wr:B                            wl:B   wr:B
```
操作：`w 变红`，`x = p`。
- 若 **p 原是红**：循环结束，p 染黑（红 + 额外黑 = 黑），消化完毕。
- 若 **p 原是黑**：p 成为新的双黑，带着额外黑继续向上循环。

**Case 3：兄弟 w 黑 + 近侄红、远侄黑** —— 旋转兄弟，转成 Case 4

> x 是左孩子时：近侄 = `w.left`，远侄 = `w.right`。

```
        修复前                              右旋(w) 后
         p:?                                   p:?
        /   \                                 /   \
     x:B*    w:B          ──右旋(w)──>     x:B*    wl:B   ← 新兄弟
            /   \                                    \
          wl:R   wr:B                                 w:R
        (近红) (远黑)                                   \
                                                        wr:B
```
操作：`wl 变黑`，`w 变红`，`右旋(w)`，`w = x.parent.right`。旋转后**远侄变红**，正好进入 Case 4。

**Case 4：兄弟 w 黑 + 远侄红** —— 变色 + 旋转父亲，彻底结束

```
        修复前                              左旋(p) 后（x=root，循环结束）
         p:?                                   w:(原 p 色)
        /   \                                 /   \
     x:B*    w:B          ──左旋(p)──>       p:B    wr:B
            /   \                           /   \
          wl:?   wr:R                     x:B   wl:?
                (远红)                    ↑ 卸掉额外黑，黑高补齐
```
操作：`w 取 p 的颜色`，`p 变黑`，`wr（远侄）变黑`，`左旋(p)`，`x = root`（强制结束）。
左旋后 x 这一侧凭空多了个黑节点 p，额外黑被吸收，黑高恢复，整棵树重新合法。

> **一句话记忆**：兄红→旋转变黑；兄黑双黑孩→上移；兄黑近红→旋兄；兄黑远红→旋父收尾。**删除最多 3 次旋转。**

## 3. 跳表（Skip List，概率型有序结构）

> 配套源码：`kvstore_skiplist.c`（在 skiplist 引擎分支里）。**Redis 有序集合 zset 的底层就是它**，所以这一节和第 8 节 Redis 强绑定，一起背。

### 3.1 核心思想 & 结构

在一条**有序单链表**之上，随机给部分节点"加高"，建出多层稀疏索引链；查找从最高层往右走、走不动就下沉一层，像坐电梯跳过大段节点。

```
level 3:  H ----------------------> 25 -----------> NULL
level 2:  H --------> 9 ----------> 25 -----------> NULL
level 1:  H --> 6 --> 9 --> 17 ---> 25 --> 30 ----> NULL
level 0:  H --> 6 --> 9 --> 17 ---> 25 --> 30 ----> NULL   ← 最底层是完整有序链表
```

```c
struct skipnode {
    char *key; char *value;
    struct skipnode **forward;   // 长度=本节点层高，forward[i]=第 i 层的后继
};
struct skiplist {
    struct skipnode *header;     // 哨兵头(key=NULL)，forward 一次开满 MAX_LEVEL(32)
    int level;                   // 当前实际用到的最高层
    int count;
};
```
要点：哨兵头节点 forward **一次开满 32 层**（省去抬高时扩容）；普通节点 forward 长度 = 它的随机层高；**level 0 永远是完整有序链表**（销毁/范围查询都顺它走）。

### 3.2 随机层高：抛硬币（概率的灵魂）

```c
int random_level() {
    int level = 1;
    while ((rand() & 1) && level < MAX_LEVEL) level++;  // P=0.5：连续正面就升层
    return level;
}
```
- P=0.5：一半节点只 1 层、1/4 到 2 层、1/8 到 3 层……**越高的层越稀疏**。
- 期望每节点指针数 = `1/(1-P) = 2`；期望最高层 ≈ `log_{1/P}(n)`；故增删查期望 **O(log n)**。
- **Redis 用 P=0.25**（不是 0.5）：每节点平均 `1.33` 个指针，更省内存，代价是层数略高一点。
- 追问「为何用概率而不像红黑树那样确定平衡？」→ **用随机性换掉旋转/修复的复杂度**：期望 O(log n)，没有最坏硬保证，但实践足够好且实现极简。

### 3.3 `update[]` 数组 —— 增删的命门（必考）

查找/插入/删除共用一套「自顶向下、逐层向右」骨架；**插入和删除还要记下每层的前驱**存进 `update[i]`，接线/解链时用：

```c
x = header;
for (i = level - 1; i >= 0; i--) {
    while (x->forward[i] && strcmp(x->forward[i]->key, key) < 0)
        x = x->forward[i];      // 这一层能往右就往右，直到下一个 >= key
    update[i] = x;              // 第 i 层"最后一个 < key"的节点 = 插入点前驱
}
x = x->forward[0];             // 底层后继 = 目标候选
```

### 3.4 插入（set）

1. 走骨架填好 `update[]`；若 `x->forward[0]` 命中同 key → 返回 1（SET 不覆盖）。
2. `random_level()` 定新节点层高；分配 node/key/value/forward，**任一步失败逐级回滚**。
3. 若新层高 > 当前 `level`：超出的那几层前驱补成 `header`，并抬高 `skip_list.level`。
4. 逐层接线（和单链表头插同理，**先接后继再改前驱**）：
```c
for (i = 0; i < new_level; i++) {
    node->forward[i]    = update[i]->forward[i];
    update[i]->forward[i] = node;
}
```

### 3.5 删除（del）

1. 同样填 `update[]` 定位 x；没命中 → 返回 1。
2. 逐层解链：某层 `update[i]->forward[i] != x`，说明 **x 没到这层，再往上也不会有，直接 break**。
3. free 掉 x。
4. 若顶部空出若干层（header 高层 forward 变 NULL），**回收 `skip_list.level`**，免得查找空跑高层。

### 3.6 复杂度 & 弱点

| 操作 | 期望 | 最坏 |
|------|------|------|
| 查 / 增 / 删 | O(log n) | O(n)（运气极差，全挤同层）|
| 范围查询 | O(log n + m) | 顺底层链走，天然友好 |

空间：期望每节点 `1/(1-P)` 个指针。

弱点（主动说 = 加分）：
1. 概率结构，**无最坏硬保证**（红黑树有严格 O(log n)）。
2. 依赖随机数质量；`rand()` 一般且是全局状态，**未加锁多线程不安全**。
3. 本实现是全局单例，且**没存 backward 指针**（不能反向遍历）、**forward 没有 span**（算不了 rank）——这俩 Redis 都补上了（见第 8 节）。

### 3.7 跳表 vs 红黑树（antirez 选跳表做 zset 的三个理由，背下来）

1. **内存可调**：靠 P 控制每节点指针数，不比平衡树费内存。
2. **范围/顺序遍历友好**：ZRANGE 就是顺着链走，cache 局部性好。
3. **实现/调试/扩展简单**：没有旋转那套；加个 span 字段就能 O(log n) 求 ZRANK，改动很小。

## 4. 高频对比题：哈希 / 跳表 / 红黑树（必考）

| 维度 | 哈希表 | 跳表 | 红黑树 |
|------|--------|------|--------|
| 增删查 | 平均 O(1)，最坏 O(n) | **期望** O(log n) | **稳定** O(log n) |
| 有序性 | 无序 | 有序 | 有序 |
| 范围 / 前驱后继 | 不支持 | 支持（顺底层链）| 支持（中序）|
| 实现复杂度 | 低 | 低（无旋转）| 高（旋转 + 修复）|
| 最坏保证 | 无（碰撞）| 概率性，无硬上界 | 有，严格 O(log n) |
| 空间 | 桶数组有空槽 | 每节点均摊 `1/(1-P)` 指针 | 每节点 3 指针 + 颜色 |
| 并发改造 | 需分段锁 | 容易（改动局部）| 难（旋转牵动大）|

> **一句话**：点查极致 → 哈希；要有序+范围+好实现+好并发 → 跳表（Redis zset）；要严格最坏上界 → 红黑树。

**工程实例（抛出来加分）**：
- **Redis** zset = 跳表 + 字典（dict）；Redis 没用红黑树
- **Java** HashMap = 数组 + 链表 + 红黑树（链长 >8 且容量≥64 转树）；TreeMap = 红黑树
- **C++** `std::map`/`std::set` = 红黑树，`std::unordered_map` = 哈希
- **LevelDB** memtable = 跳表

## 5. 针对本代码，面试官可能挑的刺（提前想好答案）

1. **线程安全**：全局 `static` 单例无锁 → 加读写锁，或分段锁（ConcurrentHashMap 思路）。
2. **hash 不扩容**：怎么 rehash？（见 1.5；Redis 的答案是渐进式 rehash，见 8.5）
3. **rbtree 递归销毁**：深树爆栈 → 改迭代 + 显式栈。
4. **value 等长更新**：MOD 总是重新 malloc → 优化为「新值不超过旧长度就原地 strcpy」。
5. **缺计数/迭代接口**：rbtree 没存 count；hash/skiplist 存了 count 但没暴露。
6. **skiplist 概率退化**：极端随机下 O(n)，无最坏保证（红黑树有）。
7. **skiplist 用 `rand()`**：质量一般且全局状态，多线程不可重入 → 换更好的 PRNG / 每线程种子。
8. **skiplist 无 backward / span**：不能反向遍历、不能 O(log n) 求 rank → 仿 Redis 补字段（见 8.2）。

## 7. 手写代码题（白板高频）

> 这几题是「哈希 + 树 + 跳表 + 指针」面试现场最常被要求白板写的。每题先写代码，
> 再背下「讲解要点」——面试官边看代码边追问，讲不出 why 等于没写对。

### 题 1：哈希桶内单链表删除

```c
// 拉链法哈希表删除 key：0 成功 / 1 不存在
int hash_del(char *key) {
    unsigned int slot = bkdr_hash(key) % table.max_slots;
    struct hashnode *node = table.nodes[slot];
    struct hashnode *prev = NULL;

    while (node != NULL) {
        if (strcmp(node->key, key) == 0) {
            if (prev == NULL)
                table.nodes[slot] = node->next;   // 删的是链头：桶直接指向 next
            else
                prev->next = node->next;          // 删的是中间/尾：前驱跨过它

            free(node->key);
            free(node->value);
            free(node);
            return 0;
        }
        prev = node;
        node = node->next;
    }
    return 1;   // 遍历完没找到
}
```
**讲解要点**：
- `prev` 记前驱是单链表删除的命门；**头节点必须特判**（prev 还是 NULL）。
- 顺序：先用 `node->next` 改好链接，**再 free(node)**——不能先 free 再读 `node->next`（悬空指针）。
- 复杂度：定位桶 O(1)，链内查找 O(链长)，哈希均匀时 O(1)。

### 题 2：左旋（红黑树/AVL 通用）

```c
// 以 x 为支点左旋：x 的右孩子 y 转上来当父亲，x 变 y 的左孩子
void left_rotate(struct rbtree_node *x) {
    struct rbtree_node *y = x->right;   // y 即将上位

    x->right = y->left;                 // ① y 的左子树过继给 x 当右子树
    if (y->left != T.nil)
        y->left->parent = x;

    y->parent = x->parent;              // ② y 接到 x 原来的父亲位置
    if (x->parent == T.nil)
        T.root = y;                     //    x 原是根 → y 成新根
    else if (x == x->parent->left)
        x->parent->left = y;
    else
        x->parent->right = y;

    y->left = x;                        // ③ x 挂到 y 的左下
    x->parent = y;
}
```
**讲解要点**：
- 三组指针**双向都要改**（孩子认父、父认孩子），漏一边就断链。
- 三个特判：`y->left` 是否 nil、`x` 是否根、`x` 是父的左还是右孩子。
- **右旋是它的完全镜像**（`left↔right` 对调），白板上写完一个直接镜像出另一个。
- 不变量：旋转保持 BST 有序性，只改高度/结构。

### 题 3：BST 删除（纯二叉搜索树，不含红黑修复）

```c
// transplant：用子树 v 顶替子树 u 的位置（NULL 版本）
void transplant(node **root, node *u, node *v) {
    if (u->parent == NULL)          *root = v;
    else if (u == u->parent->left)  u->parent->left  = v;
    else                            u->parent->right = v;
    if (v != NULL) v->parent = u->parent;
}

node *tree_minimum(node *x) {       // 子树最小值：一直往左走
    while (x->left != NULL) x = x->left;
    return x;
}

void bst_delete(node **root, node *z) {
    if (z->left == NULL) {
        transplant(root, z, z->right);          // 情况一：无左孩子 → 右孩子顶替
    } else if (z->right == NULL) {
        transplant(root, z, z->left);           // 情况二：无右孩子 → 左孩子顶替
    } else {                                     // 情况三：两个孩子
        node *y = tree_minimum(z->right);       //   找中序后继（右子树最小值）
        if (y->parent != z) {                   //   后继不是 z 的直接右孩子
            transplant(root, y, y->right);       //   先把 y 摘出来，用 y 的右孩子顶替 y
            y->right = z->right;
            y->right->parent = y;
        }
        transplant(root, z, y);                  //   用 y 顶替 z
        y->left = z->left;
        y->left->parent = y;
    }
    free(z);
}
```
**讲解要点**：
- 三种情况：0/1 个孩子直接顶替；2 个孩子用**中序后继**（右子树最小值）替换。
- 为什么选后继？→ 后继是右子树最左节点，**一定没有左孩子**，删起来简单；且它是「比 z 大的最小值」，替到 z 的位置仍满足 BST 有序。
- 对称写法也可用**前驱**（左子树最大值）。
- 红黑树版在此基础上多两步：记 `y_original_color`，删的是黑节点才调 `delete_fixup`；NULL 全部换成哨兵 `nil`。

### 题 4：跳表插入（`update[]` 模式）

```c
// 跳表插入 key：0 成功 / 1 已存在
int skiplist_insert(char *key, char *value) {
    struct skipnode *update[MAX_LEVEL] = {0};
    struct skipnode *x = sl.header;

    // ① 自顶向下，逐层记录"插入点前驱"
    for (int i = sl.level - 1; i >= 0; i--) {
        while (x->forward[i] && strcmp(x->forward[i]->key, key) < 0)
            x = x->forward[i];
        update[i] = x;
    }
    // ② 查重
    x = x->forward[0];
    if (x && strcmp(x->key, key) == 0) return 1;

    // ③ 随机层高，新层比当前高的部分前驱补 header
    int lvl = random_level();
    if (lvl > sl.level) {
        for (int i = sl.level; i < lvl; i++) update[i] = sl.header;
        sl.level = lvl;
    }
    // ④ 建节点 + 逐层接线（先接后继再改前驱）
    struct skipnode *node = make_node(key, value, lvl);
    for (int i = 0; i < lvl; i++) {
        node->forward[i]      = update[i]->forward[i];
        update[i]->forward[i] = node;
    }
    sl.count++;
    return 0;
}
```
**讲解要点**：
- `update[i]` = 第 i 层「最后一个 < key」的节点，是接线的前驱——**跳表增删的核心套路**。
- 新节点层高随机；**超出当前最高层的那几层，前驱只能是 header**，别忘了同步抬高 `sl.level`。
- 接线方向和单链表头插一致：先 `node->forward = 前驱->forward`，再 `前驱->forward = node`。
- 删除是镜像：同样填 `update[]`，逐层 `update[i]->forward[i] = x->forward[i]`，某层前驱后继不是 x 就 break。

### 进阶口头题（不一定写代码，但要能说）
- 哈希 rehash 扩容流程：新建 2× 桶数组 → 遍历旧表逐节点重新哈希搬迁 → 释放旧数组（Redis 把这步拆成渐进式，见 8.5）。
- 红黑树中序遍历输出有序序列（为什么天然有序）。
- 红黑树/跳表上做范围查询 `[lo, hi]`：找下界 + 顺序（中序后继 / 底层链）迭代到上界。
- 跳表如何 O(log n) 求 rank：每个 forward 存 span，查找路径上 span 累加（Redis 的做法）。

## 8. Redis 知识点（与本项目对应，面试串讲）

> 本项目的 hash / rbtree / skiplist 三个引擎，正好对应 Redis 里最核心的三类底层结构。
> 把「我写的玩具版」和「Redis 工业版」的差距讲清楚，是这套项目最大的面试价值。

### 8.1 zset 为什么用跳表（不是红黑树）

Redis 有序集合 zset 底层用**跳表**，作者 antirez 的三条理由（高频面试题，背原话）：
1. **内存可控**：通过调节节点升层概率（Redis 用 `P=0.25`），指针开销不比平衡树大，还能按需调。
2. **范围遍历友好**：zset 大量操作是 `ZRANGE`/`ZREVRANGE`，本质是顺链表遍历，跳表的 cache 局部性至少不输平衡树。
3. **实现简单**：没有旋转/修复，易写易调易扩展——比如加 `span` 字段实现 O(log n) 的 `ZRANK` 只需很小改动。

> 补一句：跳表**只在 zset 用**；Redis 其它有序需求没用红黑树。

### 8.2 Redis 跳表比"课本跳表"多了什么（对照本项目）

| 字段 | 本项目 `kvstore_skiplist.c` | Redis `zskiplist` | 作用 |
|------|------|------|------|
| 升层概率 P | 0.5（`rand()&1`）| **0.25** | 更省内存 |
| 最大层 | 32 | 32（`ZSKIPLIST_MAXLEVEL`）| 同 |
| backward 指针 | ❌ 无 | ✅ level 0 一个 | **反向遍历** `ZREVRANGE` |
| span（跨度）| ❌ 无 | ✅ 每个 forward 一个 | **O(log n) 求 rank**：查找路径 span 累加 = 排名 |
| 排序键 | key 字典序 | **score 排序，score 相同按 member 字典序** | zset 按分数排 |

- **backward**：只在最底层挂一条反向单指针，支持从尾往头倒着遍历。
- **span**：某 forward 跨过了多少个底层节点；`ZRANK`/`ZRANGE` 靠沿途累加 span 在 O(log n) 内算出名次，不用一个个数。

### 8.3 zset = 跳表 + 字典（dict）双结构（必考）

zset 同时维护两份结构，**指向同一批数据**：
- **跳表**：按 score 有序 → 支持 `ZRANGE`/`ZRANK`/范围查询，O(log n)。
- **字典 dict**：`member → score` 映射 → `ZSCORE`(查某成员分数)、`ZADD` 判重，O(1)。

> 一句话：**字典管"点查"，跳表管"排序/范围"，用空间换两边都快**。和本项目「rbtree 引擎单结构」对比，正是这点差距。

### 8.4 zset 的编码转换（listpack ⇄ skiplist）

小集合不值得为跳表+字典付双份内存，Redis 用**紧凑编码**起步，超阈值才升级：
- 元素少且短 → `listpack`（旧版 `ziplist`），一段连续内存顺序存。
- 超过阈值 → 转 `skiplist`（+dict）。阈值（可配）：
  - `zset-max-listpack-entries 128`（元素个数）
  - `zset-max-listpack-value 64`（单个成员字节数）
- 任一超限即转换，**且不会自动转回**。

### 8.5 Redis dict 的渐进式 rehash（呼应本项目"哈希不扩容"）

本项目哈希引擎的最大短板是**桶数固定不扩容**（见 1.5）。Redis 的工业解法：
- dict 内置**两张哈希表** `ht[0]`、`ht[1]`。扩容时不一次性搬，而是**渐进式 rehash**：用 `rehashidx` 记进度，每次增删查**顺手迁移一个桶**，再加定时辅助迁移。
- rehash 期间：查找先查 `ht[0]` 再查 `ht[1]`；新增只写 `ht[1]`。迁移完 `ht[1]` 变 `ht[0]`。
- 好处：把一次会**阻塞主线程**的大搬迁，摊成无数次微小操作（Redis 单线程，绝不能长时间卡住）。
- 扩容时机：负载因子 `used/size ≥ 1`（有 BGSAVE/AOF 子进程时放宽到 `≥ 5`，避免触发大量 COW 写时复制）；缩容 `< 0.1`。
- 哈希函数：Redis 4+ 用 **SipHash**，抗哈希碰撞攻击（hash-flooding DoS）——比本项目的 BKDR 安全。

### 8.6 Redis 五大类型的底层编码总览（背诵表）

| 类型 | 编码（小 → 大）| 关键阈值 |
|------|----------------|----------|
| String | `int` / `embstr`(≤44B) / `raw` | embstr 44 字节界 |
| List | `quicklist`（listpack 串成的双向链表）| `list-max-listpack-size` |
| Hash | `listpack` / `hashtable` | entries 128 / value 64B |
| Set | `intset`(纯整数) / `listpack` / `hashtable` | intset 512；listpack 128 |
| ZSet | `listpack` / `skiplist`(+dict) | entries 128 / value 64B |

> 记忆主线：**小数据用紧凑编码（连续内存、省指针），超阈值升级成"真正的数据结构"**。

### 8.7 高频 Redis 面试速答

- **Q：zset 为什么不用红黑树？** → 8.1 三理由（内存可控 / 范围遍历友好 / 实现简单）。
- **Q：跳表查找/插入复杂度？** → 期望 O(log n)，靠随机层高，无最坏硬保证但实践够用。
- **Q：zset 怎么同时支持 O(1) 查分和 O(log n) 排名？** → 跳表 + 字典双结构（8.3）。
- **Q：`ZRANK` 怎么做到 O(log n)？** → forward 带 span，查找路径累加（8.2）。
- **Q：Redis 大哈希扩容会卡住吗？** → 不会，渐进式 rehash 把搬迁摊开（8.5）。
- **Q：跳表 P 为什么取 0.25？** → 平均 1.33 指针/节点，比 0.5 省内存，层高只略增。
